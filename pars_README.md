и полный проход по реальному сайту пока не проверены.

## Первый запуск

Положите `pars.py` и `Артикулы — копия.csv` в одну папку. CSV: UTF-8,
разделитель `;`, колонка `Артикул`. Начальные нули сохраняются.

В терминале этой папки:

```powershell
python -m pip install requests playwright
python pars.py
```

Скрипт откроет установленный Chrome или Edge с отдельным профилем.
Выберите город, дождитесь загрузки и нажмите Enter в терминале.
Скрипт попробует найти первый артикул сам. Если поиск не распознан,
он попросит выполнить поиск этого артикула вручную и нажать Enter.
Проверку сайта, если она появится, проходит пользователь.

После успешного ответа поиска скрипт сохраняет актуальные настройки запроса
(включая ключ и регион), User-Agent и куки, закрывает своё окно браузера
и получает цены. Куки магазина передаются только соответствующим доменам;
они не подменяют ключ внешнего поискового сервиса.

Если Chrome/Edge не установлен:

```powershell
python -m playwright install chromium
python pars.py --browser chromium
```

## Повторный запуск

По умолчанию этап 0 выполняется каждый раз. Использовать сохранённую сессию:

```powershell
python pars.py --skip-browser
```

Только обновить настройки и куки:

```powershell
python pars.py --refresh-only
```

Другие файлы:

```powershell
python pars.py --input "мой список.csv" --output "цены.csv"
```

Результат: `price.csv`, открывается в Excel. Добавлена колонка `Статус`,
которая различает отсутствие товара, отсутствие цены и ошибку запроса.
При ошибке начальной проверки существующий результат не перезаписывается.
В процессе строки сохраняются сразу. Код завершения 1 означает ошибки.
При обычном запуске файлы по умолчанию ищутся рядом со скриптом.

Папка `.proconsim` содержит куки, ключ и отдельный профиль браузера.
Храните её локально, не публикуйте и не отправляйте другим людям.
Рабочий профиль Chrome/Edge скрипт не использует.

Если магазин сменил Diginetica на другой сервис или изменил структуру ответов,
скрипт остановится с пояснением. Этап 0 не гарантирует обход блокировок;
перенос куки в requests не воспроизводит браузерное соединение полностью.
